# 超维科研工作流 v0.2 · 工程验收候选

科研是超维成长下与伴学平行的独立模块。未来超维成长统一接入伴学、科研、项目、规划、链接五个模块；当前后三项仅预留模块描述，不冒充已实现。

## 三层职责

| 层 | 职责 | 实现 |
|---|---|---|
| 审美层 | 判断问题与方法是否适配、区分观察与解释、寻找反例、检查主张和证据的关系 | `aesthetic/rules.py`、`aesthetic/workflow.py`；质性、人文、设计、实证与模拟分别给出判断要点 |
| 功能层 | 契约、项目授权、事务、检索、模型调用、任务状态、实验与模拟执行 | `functional/service.py` 保留 v1；`service_v2.py`、`jobs.py`、`executors.py`、独立 `worker.py`；内部包装选定 Skill |
| 资产层 | 项目范围引用、版本、SHA256、页码与字符定位，以及对传入文字的确定性检索 | `assets/references.py`、`assets/retrieval.py`；保存与读取的授权及数据库访问由功能层执行 |

伴学学科工作区与科研项目数据库互不嵌套。共享本机身份、HTTP/MCP门面和模型配置；资料联动只读取明确选择的本人伴学文字资料，核对修订与哈希，不改变伴学当前学科。

## 从哪里开始

1. 用原来的本机入口打开程序，完成本人身份设置，点击“超维科研”。
2. 建立项目，写清问题、情境、希望看到的变化和资源限制。
3. 在“资料与检索”粘贴文字或导入原件。支持 UTF-8 文字与含文字 PDF，原件最大8MB，PDF最多50页；扫描件OCR、Office转换尚未纳入首版。
4. 检索项目内资料，或主动向 Crossref/OpenAlex/arXiv 发送检索词。记录检索范围、时间、失败源与纳入/排除理由；元数据不能充当正文证据。
5. 在“方向与计划”先保存本人方向、比较标准、反例与选择理由。可生成上游探索底稿；AI候选需先在主入口设置模型，再明确选择要发送的资料。
6. 质性、人文或设计研究可直接以计划和材料分析形成成果。需要比较测试时再保存实验设计，生成随机分配、两水平全因子或拉丁超立方计划表。
7. 可运行固定的有限时段排队模型，比较窗口数。记录参数来源、假设、单位、重复次数与基准种子；可关联项目依据，选择本人实测时必须选择依据。来源类型是作者声明，完整性校验不认证实测真实性。可取消并重试。每方案置信区间来自独立重复均值，不是现实改善证明。
8. 在“成果与复盘”写主张、性质、原文摘录、局限和帮助。系统检查所引版本与位置，不自动认定语义支持。可保存反馈、修订简报和导出Markdown/完整JSON。

## 运行与续接

源码运行保留Python3.11基础环境；科研执行使用独立Python3.12。执行 `powershell -File scripts/setup_research.ps1` 安装锁定依赖，或加 `-VerifyOnly` 检查已安装环境。模型为可选能力，调用者使用自己的配置；未配置也能完成手工研究流程。

科研任务保存在项目数据库，状态包括等待、执行、成功、失败、取消、中断与超时。任务在产品锁外执行；输入引用固定于发起时，完成前重查来源。异常退出后心跳超过75秒标为中断，需明确重试，不自动重复外部请求。首版最多2个执行线程，每项目最多4个活动任务；单个计算/解析执行最多50秒、输出最多12MB。后台结果可与新记录并存，修订同一资产仍需冲突检查。

项目JSON是可审查归档，包含原件和历次记录；设备身份、配对密钥与全部模块恢复使用原入口的加密备份。不要公开真实项目归档。

## 验收边界

当前文档随实现更新，最终通过项以 `artifacts/research-workflow-acceptance.json`、真实传输记录、浏览器记录与新构建记录为准。源码测试、冻结程序实测、模型服务实连、领域审定、现实校准、真实使用与公开发布分别记录。合成案例不证明学习收益或现实改善；未执行项保留未运行。
